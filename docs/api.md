# video API reference

Every public declaration of the package, by module, with its comment from the source.
Generated by `tools/gen_api.py`; edit the comments in `src/`, not this file.

- [`<video>`](#video)

## `<video>`

`<video>`: video playback for apps on eskiu-lang/ui. use_video opens a video file or stream
in the platform's player (AVPlayer on iOS, MediaPlayer on Android, an HTML `<video>` on the
web and the desktop), which plays its sound too; VideoView shows it, and use_video_frames
hands its decoded pictures to Eskiu, as YUV planes (RGBA on the web) laid out like
ui-camera's CameraFrame, so `<gpu/yuv>` draws either.

### VideoStatus

```eskiu
enum VideoStatus { VideoLoading, VideoReady, VideoPlaying, VideoPaused, VideoEnded, VideoFailed }
```

What a player is doing: opening its source, ready to play (paused at the start),
playing, paused, at the end (with loop off), or failed (VideoPlayer_error says why).

### VideoOptions

```eskiu
struct VideoOptions {
    bool autoplay;
    bool loop;
    bool muted;
    float volume = 1.0;
    float rate = 1.0;
}
```

How use_video starts and plays: start playing once ready (autoplay), start again at the
end (loop), no sound (muted), the volume from 0 to 1 and the speed (rate, 1 is normal).
A change from one render to the next is applied to the playing video.

### VideoPlayer

```eskiu
struct VideoPlayer {
    int id;
    int status;
    int64 duration_ms;
    int width;
    int height;
    String error;
    *Signal<int> changes;
    int frame_users;
    int frame_width;
    int frame_height;
}
```

A video in the platform's player, kept by use_video for as long as its scope is mounted.
Read it with the VideoPlayer_ functions: status, duration and size subscribe the reader,
so a component that shows them renders again when they change. `id` is the platform's
player (0 for none).

### video_resolve

```eskiu
string video_resolve(string source)
```

Where `source` is for the platform: a URL (it has "://", or is a blob: or data: URL) or an
absolute path as it is; any other name is a file of the app's assets/, as a path on iOS
and Android (ui_asset_path), and by its name, a URL relative to the page, on the web and
the desktop. The result is from malloc; the caller frees it.

### use_video

```eskiu
*VideoPlayer use_video(string source, VideoOptions options)
```

The video at `source` in the platform's player, open while the scope is mounted: a URL
(http, https, a file:// URL, a blob: URL on the web), an absolute file path, or the name of
a file in the app's assets/. The platform plays its sound. A new source opens it in place
of the old one; new options are applied to the playing video. The player is closed when
the scope unmounts.

### VideoFit

```eskiu
enum VideoFit { VideoContain, VideoCover, VideoStretch }
```

How VideoView fits the picture in its box: the whole picture at its aspect ratio
(VideoContain, bars where it does not fill), filling the box and cropping
(VideoCover), or stretched to the box (VideoStretch).

### VideoView

```eskiu
void VideoView(Style style, *VideoPlayer player, VideoFit fit)
```

The player's picture, shown by the platform in the box the layout gives it (Eskiu does not
touch the frames). One VideoView per player. On Android a player sends its picture to one
place: while use_video_frames is on for it, the frames get the picture and the view stays
black.

### VideoFormat

```eskiu
enum VideoFormat { VideoNV12, VideoNV21, VideoI420, VideoYUV420, VideoRGBA }
```

How a frame's pixels are laid out; the values of ui-camera's CameraFormat and
`<gpu/yuv>`'s GpuYuvFormat. NV12: a Y plane, then one plane of interleaved U and V (U first).
NV21: the same with V first. I420: Y, U and V planes, chroma a quarter of the size.
YUV420: Y, U and V planes whose chroma samples are `pixel_stride` bytes apart. RGBA: one
plane of 4 bytes a pixel (the web).

### VideoMatrix

```eskiu
enum VideoMatrix { VideoBT601, VideoBT709 }
```

The matrix a frame's YUV is encoded with: BT.601 (standard definition) or BT.709 (HD).

### VideoPlane

```eskiu
struct VideoPlane { *uint8 data; int row_stride; int pixel_stride; int64 size; }
```

One plane of a frame: `data` (borrowed for the handler's call), the bytes from one row to
the next, from one sample to the next in a row (2 in NV12 and NV21's chroma plane), and the
bytes readable from `data`.

### VideoFrame

```eskiu
struct VideoFrame {
    int width;
    int height;
    int format;
    int plane_count;
    VideoPlane[3] planes;
    int rotation;
    int64 timestamp_ns;
    bool front;
    int matrix;
    bool full_range;
}
```

A decoded frame, laid out like ui-camera's CameraFrame and `<gpu/yuv>`'s GpuYuvImage (cast
a *VideoFrame to a *GpuYuvImage to upload it). `width` and `height` are in pixels as
decoded; `plane_count` planes are set, as `format` says. `rotation` (0, 90, 180 or 270)
is how far to turn it clockwise to be upright (a phone's portrait video is stored
landscape); `timestamp_ns` is the frame's time in the video; `front` is always false
(it keeps the shared layout); `matrix` and `full_range` say how its YUV maps to RGB.

### VideoFrameOptions

```eskiu
struct VideoFrameOptions {
    int max_width;
    int max_height;
}
```

What use_video_frames asks for: at most this size (0 for the decoded size), kept to the
picture's aspect ratio. iOS and the web scale down to it; Android gives the decoded size.

### VIDEO_FRAME_INFO

```eskiu
const int VIDEO_FRAME_INFO = 24;
```

How many int64 values video_native_frame_acquire fills: width, height, format,
plane_count, rotation, front, matrix, full_range, timestamp_ns, then for each of 3 planes
its data pointer, row_stride, pixel_stride and size.

### video_frame_read

```eskiu
bool video_frame_read(*int64 info, *VideoFrame out)
```

The values video_native_frame_acquire filled, checked, as a frame; false when they do not
describe one (unknown format, a missing plane, strides or sizes that do not cover the
pixels), so a handler never reads outside a buffer.

The latest render's frame handler, its options and the player it reads, kept in the hook's

### video_release_frame_handler

```eskiu

```

Frees a frame handler's closure; use_video_frames calls it when it replaces or drops the

### video_deliver_frame

```eskiu
void video_deliver_frame(int id, fn(*VideoFrame)->void handler)
```

Borrows the player's latest frame from the platform, hands it to `handler` and gives it
back.

### use_video_frames

```eskiu
void use_video_frames(*VideoPlayer player, VideoFrameOptions options, escaping fn(*VideoFrame)->void on_frame)
```

`on_frame` gets `player`'s decoded frames while the scope is mounted, on the UI thread,
as the video plays (paused, no new ones come); the frame and its planes are borrowed for
the call (convert or copy what you keep). A frame that arrives while it runs replaces the
one waiting: a slow handler gets fewer, newer frames, never a queue. Call it after
use_video, in the same scope or one inside it.

### VideoYuvCoeffs

```eskiu
struct VideoYuvCoeffs { int y_offset; int y_scale; int v_r; int u_g; int v_g; int u_b; }
```

The fixed-point (1 << 16) coefficients that turn one matrix and range's YUV into RGB.

### video_yuv_coeffs

```eskiu
VideoYuvCoeffs video_yuv_coeffs(int matrix, bool full_range)
```

The coefficients for `matrix` (a VideoMatrix), full range (Y 0-255, chroma 0-255 about
128) or limited (Y 16-235, chroma 16-240).

### video_clamp8

```eskiu
uint8 video_clamp8(int value)
```

A fixed-point value rounded to 0-255.

### video_yuv_to_rgb

```eskiu
void video_yuv_to_rgb(*VideoYuvCoeffs c, int y, int u, int v, *uint8 rgb)
```

One pixel's Y, U (Cb) and V (Cr) as R, G and B into `rgb[0..2]`.

### VideoFrame_out_width


The frame's width once turned upright (to_rgba with `upright`), or as it is.

### VideoFrame_out_height

```eskiu
int VideoFrame_out_height(*VideoFrame self, bool upright)
```

The frame's height once turned upright, or as it is.

### VideoFrame_to_rgba

```eskiu
void VideoFrame_to_rgba(*VideoFrame self, *uint8 out, int out_stride, bool upright)
```

The frame as RGBA (alpha 255) into `out`, `out_stride` bytes a row, with its own matrix
and range; turned by its rotation when `upright` (out_width and out_height give the size
`out` needs). Pure Eskiu, on the calling thread; `<gpu/yuv>` does the same on the GPU.
